Student 1 — GlowRush system architecture blueprint

A judge-facing visual set for the overall platform: system context, HLD, container boundaries, deployment, StormShield admission control, communication, bottlenecks, scalability and failure recovery. The diagrams are deliberately separated so each one explains a single architectural decision without overloading the reader.

10,000 concurrent buyers 100 units of flash-sale stock ~10k RPS normal Up to ~500k RPS flash-sale reasoning StormShield admission control PostgreSQL + Redis + RabbitMQ
Traffic entryCDN/WAF → Load Balancer → API Gateway → StormShield is the controlled front door.
Stock authorityInventory & Reservation Service owns stock consistency; StormShield never owns inventory.
ScalingEdge caching, horizontal service replicas, queueing, Redis and database scaling absorb the flash-sale burst.
RecoveryTimeouts, retries, circuit breakers, async events, DLQ and reconciliation handle dependency failures.
